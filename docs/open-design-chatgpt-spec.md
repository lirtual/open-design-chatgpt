# OpenDesign for ChatGPT 技术规格

## 1. 问题、方案与交付状态

用户希望在 ChatGPT Web 中复用 OpenDesign 的设计指导、本地项目、预览和导出，由 ChatGPT 完成创建与修改，减少重复部署、模型调用和长期维护成本。

方案：ChatGPT 是唯一自主 Agent；通过安全 MCP 连接驱动本地 OpenDesign 的确定性能力。项目文件以 workspace 为准，项目元数据继续由现有 daemon 管理。复用同一套 MCP 业务契约、设计资源、预览和导出实现。

本规格综合已接受的 CONTEXT、19 份 ADR、审查修订及本轮有限源码检查。`ready-for-agent` 表示可以执行下述分阶段工作，不表示 Web 账号接入、PDF 导出或安全边界已验证通过。必须先完成 G0–G2，再做最终插件分发。没有配置本项目的 issue tracker；本规格按 to-spec 的文件回退方式发布。后续若需关联任务系统，运行 `/setup-engineering-workflows`，不影响先执行验证。

## 2. 用户故事

1. As a 设计用户, I want 在 ChatGPT Web 使用 OpenDesign, so that 我能在同一对话中完成设计工作。
2. As a 本机用户, I want 只授权选定项目目录, so that 其他本地资料不被访问。
3. As a 设计用户, I want 查看已授权项目并准确选中一个, so that 修改不会落到错误项目。
4. As a 设计用户, I want 创建新项目, so that 新作品拥有独立内容和名称。
5. As a 设计用户, I want 使用已有设计规则和模板, so that 输出保持一致风格。
6. As a 设计用户, I want 在没有设计规则时得到明确提示并继续采用合理默认值, so that 不会因缺少文件阻断工作。
7. As a 设计用户, I want 创建带图片的静态页面和演示文稿, so that 能完成常见设计交付。
8. As a 设计用户, I want 修改或删除指定文件, so that 可以持续迭代作品。
9. As a 同时使用本地编辑器的用户, I want 旧内容修改遇到冲突时停止覆盖, so that 已保存的工作不会无声丢失。
10. As a 设计用户, I want 修改部分失败时知道哪些已完成, so that 可以准确恢复工作。
11. As a 设计用户, I want 在同一台电脑的浏览器打开预览, so that 可以检查实际效果。
12. As a 设计用户, I want 下载包含必要资源的 HTML 交付物和可打开的 PDF, so that 可以脱离对话使用作品。
13. As a 设计用户, I want 缺少渲染组件、文件过大或导出超时时得到明确原因, so that 知道如何继续而不反复盲试。
14. As a 设计用户, I want 网络中断后确认上次操作结果再恢复, so that 不会重复创建项目或破坏内容。
15. As a 本机用户, I want 撤销访问后阻止后续操作, so that 能控制电脑上的访问权限。
16. As a 安装用户, I want 知道连接是否就绪以及缺少哪些条件, so that 可以完成安装并排查问题。
17. As a 安装用户, I want 明确了解同机预览的限制, so that 不会误以为手机或异地设备也能打开本地地址。
18. As a 维护者, I want 复用经过验证的上游版本和小范围补丁, so that 升级不会引入两套长期分叉的实现。

## 3. 源码检查事实与证据边界

本轮通过 GitHub 读取默认分支文件，未克隆、构建或运行项目。以下 SHA 是文件 blob SHA，不是仓库 commit；G0 必须固定完整 commit 并重新核对。默认分支读取不构成一致的发布基线。

|---|---|---|
| `apps/daemon/src/mcp.ts` | stdio MCP 代理 daemon；已有项目创建、文件创建/写入/删除及读取；还暴露 Agent Run 等额外工具 | `7d10e6f4b45494803a248668ba4250f021f11a38` |
| `apps/daemon/src/cli.ts` | `od mcp` 加载现有 MCP；导出调用既有 daemon 路由；PDF CLI 指向图像 PDF 路径 | `31693001e25e66be531c46fd675e872062d16183` |
| `apps/daemon/src/import-export-routes.ts` | 存在 HTML/PDF 导出路由；桌面 PDF 和截图路径存在 renderer 可用性检查 | `7c698f7353624ae951cc806805f67e943a1df2cb` |
| `apps/daemon/package.json` | package 名为 `@open-design/daemon`，提供 `od` bin 和包级测试/构建 | `13328a4d2a8f378291d0868d5205dcd2ba3eb456` |

已读根、apps 和 e2e 的 AGENTS.md：daemon 拥有业务 API；共享 DTO 使用既有 contracts；测试复用 tools-dev 生命周期与 e2e suite；数据目录遵守上游根 AGENTS.md 的权威规则，不另定义具体数据路径。

发现的实际差异：

- 旧计划“现有 MCP 主要只读”已过时。已有 `create_project`、`create_artifact`、`write_file`、`delete_file`，应增强现有操作，不另造同义工具。
- `write_file` 当前向 daemon 发送全量内容，所检查的 MCP 参数没有条件哈希；是否已有底层版本保护仍须核实。
- `get_file` 可能分页；读取窗口不等于完整文件，不能拿一页内容覆盖全文件。
- `get_project` 已提供预览地址的契约，不应无依据新增一个 preview server。
- `create_project` 存在 workspace 错误后不带原 headers 重试的分支。远程受限入口必须 fail closed；不得把该回退直接复用于本集成。
- MCP 还包含 `start_run`、登录、Agent 列表和 brief widget，以及与当前产品定位不一致的 server instructions。仅靠 Skill 说“不调用”不足以满足受限工具边界。
- 已有桌面渲染器依赖意味着“无需第二套渲染器”成立，但“纯 headless daemon 必然能导出 PDF”尚不成立。可复用已安装桌面渲染组件；不可偷偷用第二 Agent 或云渲染兜底。

## 4. 范围与架构边界

首版支持同机 ChatGPT Web、本地运行中的 OpenDesign、静态 HTML/CSS/浏览器 JS 页面、静态 Deck、已有或受控导入的本地图片、设计规则、预览、HTML/PDF 交付。用户电脑与 runtime 需要在线。

| 模块 | 职责 | 禁止承担 |
|---|---|---|
| 集成 Skill/分发包 | 工作流、资源定位、工具使用指导、安装说明 | 保管第二份项目、启动第二 Agent |
| 安全 MCP 传输 | 认证关联、连接与请求传输 | 渲染、项目数据库、默认转发浏览器站点 |
| 原有 OpenDesign MCP | 工具注册、参数校验、受限入口策略、转交 daemon | 第二套项目/文件实现 |
| daemon 及已有服务 | 项目、文件、授权、元数据、预览/导出 | 新的云端产品 |
| workspace | 项目源文件和物化设计规则 | 保存传输凭据 |
| 原有预览/renderer | 派生展示及导出字节 | 执行用户可写任意本机脚本 |

复用同一 MCP 实现，为此连接选择受限工具集合，并在调用分派端同样拒绝不允许的工具；不能仅从 tools/list 隐藏。若上游已有 profile/allowlist 则复用，否则增加一个简单配置，不设计通用策略语言。为该入口调整相关 instructions，使其不要求 Cloud/Local Codex 或 Agent Run 工作流。其他客户端兼容性必须保持。

## 5. 工具与数据契约

下表规定逻辑行为，已有工具名保留；缺失操作在 G0 对齐现有 contracts 后确定名称。本文的逻辑字段需要映射到实际 Schema，不能把未核实的字段当成既有 API。

| 能力 | 现有入口/复用方向 | 必须满足的契约 |
|---|---|---|
| 项目列表/读取 | `list_projects`、`get_project` | 仅授权项目；返回稳定 ID、项目入口和可用预览信息；不泄露未授权路径 |
| 项目创建 | `create_project` | 显式授权范围、稳定请求/项目标识；重复请求返回原结果或明确冲突；不启动 Run；授权失败不降级 |
| 文件发现/读取 | `list_files`、`get_file`、必要时 `get_artifact` | 项目 ID、相对路径；完整性/分页标识、字节数及完整原始字节的版本指纹；截断必须显式呈现 |
| 新建 Artifact | `create_artifact` | 目标不存在才创建；复用 manifest 机制；返回确认后的路径与版本信息 |
| 文件写入 | `write_file` | 显式项目 ID、路径、内容、编码和前置版本/不存在条件；空文件可正确写入；返回实际新版本 |
| 文件删除 | `delete_file` | 显式项目 ID、路径、前置版本；不扩展为目录递归或整项目删除 |
| 设计规则/模板 | 现有资源读取或所需的薄工具包装 | 按需获取正文及必要素材；记录来源版本；项目缺少 DESIGN.md 时明确缺失，不捏造已有规则 |
| 预览 | 优先 `get_project` 现有 URL | 同机可访问、只指向授权项目；不得宣称 MCP Tunnel 提供 HTTP 预览 |
| HTML/PDF 导出 | 对原导出路由的薄 MCP 包装 | 明确项目、入口、格式；返回实际成功结果与可获取文件；不返回任意本机路径作为下载成功证据 |

### 5.1 修改、并发与恢复

整文件覆盖前必须获取完整文件；分页读取要确认所有页属于同一指纹，否则重新读取。版本指纹作用于原始字节；若上游无等效机制，用 SHA-256 文件哈希，不创建 revision 数据库。

在 daemon 权威写入路径执行条件校验与临时文件替换，并串行化同一路径的受管修改。创建使用“必须不存在”条件；删除校验期望版本。版本不匹配不写入，返回冲突、当前指纹及重新读取提示。多文件操作逐项报告，不声称整体原子性，不自动回滚覆盖用户后续修改。

必须准确说明保护边界：daemon 锁不能约束任意外部编辑器在检查与替换之间写文件。验收至少覆盖修改在请求前已落盘及受管并发写入；若平台没有跨进程保护，就要求同一文件避免同时保存，并记录此残余竞态，不声称完全消除所有外部写入竞态。不能为此擅自引入分布式锁或版本服务。

连接丢失时，写入结果为未知，先读取验证；项目创建使用同一稳定标识查询或重试，不能重新分配标识。已有项目重试必须校验范围与请求身份，不能仅凭同名判断是同一次操作。复用现有持久化字段/唯一约束，不另建任务平台。

### 5.2 认证与文件边界

连接绑定本地授权范围；授权策略不可被模型参数扩大。所有工具及派生 URL 都校验项目归属。授权缓存必须在撤销后失效；授权错误直接拒绝，不允许去掉凭据后重试。MCP 的 tool annotations 用于描述行为，不作为访问控制。

路径解析覆盖编码、绝对路径、父路径、符号链接及 Windows junction，不能仅检查字符串前缀。图片输入复用已有文件/上传能力；不得假设 ChatGPT 附件在本机存在。无法通过受支持输入方式取得图片时，引导用户将图片放入授权项目；不增加任意 URL 下载代理。

预览使用原有隔离机制；固定 renderer 无 Node 集成或任意脚本启动能力。不得通过项目 package.json、构建配置或导出入口运行可写命令。传输凭据不写入项目、不展示到模型返回值，认证日志按既有机制脱敏。

### 5.3 预览、导出与限额

同机浏览器访问本地地址；需要的认证复用现有机制，不暴露整个 daemon 到公网。复用 renderer 可以要求已有 Desktop 运行；安装检查必须明确这一条件。缺 renderer 返回可诊断错误，不能将 HTML 成功当作 PDF 验收通过。

优先复用现有 standalone HTML 导出；若资源不能物化，明确告知不可自包含或返回保留依赖的目录包，不能悄悄交付缺图文件。PDF 验证中文、分页、Deck 页面及图片完整性；不承诺可编辑 PPTX。

同步导出使用上游有效限额，并受实测 MCP 时限约束。G0 必须记录具体最大文件/请求字节、总导出大小、执行时限与清理行为；现有值缺失时在实现配置中补单一默认值并通过边界验证。本文不捏造平台限额。超限在可行时提前拒绝；取消或超时清理派生临时内容，不删除源文件，不遗留无管理进程。

### 5.4 失败结果

复用上游错误结构；缺失时补最小的稳定错误类别、可读原因、是否可重试及操作结果是否已知。至少区分：未授权/已撤销、项目或文件不存在、前置版本冲突、范围越界、输入或编码错误、读取截断、能力缺失、runtime 不在线、renderer 不可用、导出超限/超时、写入结果未知。禁止笼统地把所有错误归为“没有权限”。

## 6. 资源、Schema 与兼容策略

集成仓库保存薄 Skill、已选上游资源、来源版本与许可证、安装/兼容说明。仅封装闭环必需的少量 Skills。检查正文中的 Shell、脚本、Run 和资源路径要求；保留设计内容，适配执行步骤。插件 metadata 以目标 Web 入口实测支持的格式为准，不把 `.codex-plugin` 或 MCP 声明视为 Web 安装保证。

不新增数据库、Project/Artifact 实体或迁移框架。需要的请求身份、授权关联或版本条件优先复用现有 schema；确需新增字段时在既有持久化所有者内作最小兼容扩展，G0 记录具体字段及迁移。没有验证之前不宣称“零 schema 改动”。

MCP 新增参数尽量兼容现有调用方，但本受限入口必须强制要求写入前置条件；不得为了兼容其他客户端而弱化本入口。通用能力提交上游；交付可使用固定 commit 的最小补丁分支，记录删除条件。兼容检查使用已验证版本、tools/list 及必要参数，不新增 `mcpApi` 协商协议。

## 7. 分阶段实施与退出条件

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| G0：基线与能力核实 | 固定完整 commit；核对本文 source seams；读取相关层级指南；确认文件保护、资源加载、导出依赖与实际限额 | 输出一份能力映射和最小改动表，区分现有/需包装/需修复/不可满足 |
| G1：真实账号接入 | 使用官方支持且实际可用的连接方式；本地授权；发现受限工具并完成一次可逆写入 | 目标 ChatGPT Web 成功调用；无超范围工具可调用；记录失败或必要设置 |
| G2：完整产品闭环 | 规则读取、静态页面及 Deck 创建修改、本地图片、预览、HTML/PDF 下载；完成边界与恢复验收 | 下列验收矩阵通过，且未启动第二 Agent；失败则先局部修复，重大范围变更重新评估 |
| G3：分发与维护 | 完成薄 Skill/插件打包、兼容说明与上游补丁；如确有重复配置再封装连接命令 | 目标账号从实际分发入口安装并重跑核心闭环；安装前提和已知限制清楚 |

G1 可先测试 App 与工具，不等于完成插件交付。G3 必须验证实际 Skill 加载与插件安装。当前平台入口不可用时记录阻塞；不能自行降级成仅 Codex 版本后宣称满足 Web 目标。

## 8. 测试与验收矩阵

主测试接缝为真实 MCP 请求 → daemon → 授权临时项目；不为内部函数增加模拟层。复用 `e2e/lib/tools-dev/` 及既有 Vitest suite 管理 runtime。浏览器仅覆盖实际预览、下载和状态更新；Playwright 复用上游 suite，不手写平行生命周期。ChatGPT 真实账号安装属于发布前人工/受支持 UI 验收，不能用 mock 冒充通过。CI 不依赖用户凭据。

完成报告必须列出：完整 commit、补丁版本、真实账号入口、工具 Schema、renderer 运行条件、配置限额、验收证据、失败项和残余竞态。只记录文件 blob SHA 不满足交付基线要求。

## 9. 明确不在范围内

- OpenDesign Cloud、新账号体系、新数据库、新 Artifact 服务或第二套业务 runtime。
- 第二 Agent、Agent Run、通用 Shell、任意 Node/React 构建、依赖安装与服务端程序。
- 手机/异地预览、云端同步、公共目录审核、自建通用 Tunnel 平台。
- Apps SDK 内嵌编辑器、首版 Widget、自建渲染器、视频或 PPTX 导出。
- 自定义 Patch/Revision 服务、强制 Git、多文件事务、通用任务队列或分布式锁。
- 自定义能力协商协议、全量上游 Skills 镜像、daemon API 全量 MCP 化。
- 首轮即建设跨平台安装器或后台进程管理器。
